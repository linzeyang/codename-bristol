# 代码安全性评估报告

> 评估对象：声屿原型（`apps/api`、`apps/web`、Docker 部署、种子与文档）
> 评估日期：2026-11-14
> 方法：OWASP Cheat Sheet 导向的代码审计 + 数据流追踪 + 自动化测试复核
> 结论：**未发现 High/Critical 级别的可利用漏洞。** 已修复两处加固项；残留风险均为原型/部署边界事项，见第 5 节。

## 2. 关键安全控制（已验证）

### 2.1 认证与会话

- 密码使用 **bcryptjs**（cost 11）哈希；种子账号同样哈希，仓库中无明文或固定哈希凭据（`apps/api/src/auth/passwords.ts`、`seed/index.ts`）。
- 会话为 **HttpOnly + SameSite=Lax Cookie** 中的 HS256 JWT（`jose`），有效期 7 天，签发者/受众校验（`auth/tokens.ts`）。
- Token 内含 `token_version`，服务端每次请求重新读取用户并比对；修改密码与「所有设备退出」都会递增版本，使旧令牌立即失效（`routes/account.ts`、`app.ts`）。
- 角色与方案从数据库读取，不信任令牌中的旧角色；管理员接口在服务端再次校验（`routes/admin.ts`）。
- 登录错误统一为「邮箱或密码不正确」，不区分账号是否存在；注册接口会提示邮箱已注册（见残留风险 5.6）。

### 2.2 授权与对象级访问

- 所有用户级查询使用会话用户 ID，不接受客户端传入的 `user_id`，不存在水平越权参数。
- 歌单更新/删除/加曲/排序前执行 `assertOwner`；编辑精选歌单不可修改；私有歌单只对所有者可见（`routes/playlists.ts`、`services/catalog.ts`）。
- 喜欢、关注、收藏、播客关注在切换前校验目标资源存在；表名/列名来自固定映射，不拼接用户输入（`routes/library.ts`）。
- 账户导出、修改、删除、订阅切换均作用于 `request.user.id`（`routes/account.ts`、`plans.ts`）。
- 演示账号分为 `listener` 与 `admin`，听众访问管理接口返回 403（测试覆盖）。

### 2.3 注入与 XSS

- 数据库访问全部参数化；动态 SQL 只来自固定常量（列清单、排序枚举、`COLUMN_MAP`），用户值进入 `$n` 参数（`services/catalog.ts`、`routes/settings.ts`、`routes/library.ts`）。
- Zod 对邮箱、密码、标题、描述、曲目字段、查询参数做长度/枚举/数值范围校验；请求体上限 64 KB（`app.ts`）。
- 前端无 `dangerouslySetInnerHTML`、`innerHTML` 注入、`eval`、动态脚本；歌词、昵称、曲名等全部由 React 文本节点渲染。
- 前端生产构建由 Node 静态服务设置严格 CSP：`script-src 'self'`、`object-src 'none'`、`frame-ancestors 'none'`，仅允许内联样式（React `style` 属性需要）（`apps/web/server.mjs`）。
- 搜索词、向导问题等用户内容在 URL 中通过 `encodeURIComponent` 编码，渲染为文本。

### 2.4 CSRF 与跨域

- 不启用宽泛 CORS；Web 与 API 同源部署（Node 反向代理），减少跨域面。
- 变更请求要求 **Origin 白名单**（localhost/127.0.0.1 的 5173/8080，可由环境变量覆盖）；非 JSON 表单无法被 Fastify 解析，返回 415。
- 会话 Cookie `SameSite=Lax`，跨站 POST 不携带；`HttpOnly` 防止脚本读取；生产可设 `COOKIE_SECURE=true`。
- 测试覆盖「未知 Origin 写操作返回 403、白名单 Origin 成功」。

### 2.5 速率限制与拒绝服务

- 全局每 IP 300 次/分钟，登录/注册 12 次/分钟，修改密码 10 次/分钟，向导 30 次/分钟（生产模式启用，测试模式跳过）。
- 请求体 64 KB；副接口返回数量受限（搜索/列表/队列），避免无界响应。
- 音频为固定 8 个 45 秒文件，静态服务按 Range 代理，无用户上传入口。

### 2.6 数据保护与日志

- DTO 与导出不包含 `password_hash`；测试断言导出内容不含该字段。
- Pino 对 `cookie` / `authorization` 做 redact；新增请求序列化器，**日志 URL 去掉查询串**，避免搜索词写入日志。
- 隐私模式在服务端执行：`POST /api/history` 检查 `private_session` 后直接返回 `recorded:false`，不写历史。
- 播放队列保存在浏览器本地；登出时通过 `sy:logout` 事件清空队列与推荐理由，刷新恢复队列时也会剥离个性化理由，避免共享设备上的跨账号信息残留。
- 账户导出需要有效会话，通过 `Content-Disposition` 下载；删除账户要求密码 + 完整邮箱双重确认，并级联删除个人数据。
- 种子数据中的「播放量」仅作为展示；本次审计移除了 `/api/history` 对公开 `play_count` 的递增，避免任何登录用户刷高排行数据。

### 2.7 外部 LLM 与 SSRF

- `LLM_BASE_URL/LLM_API_KEY/LLM_MODEL` 仅从服务端环境变量读取，用户无法控制目标地址；无用户传入 URL 的请求能力。
- 用户问题作为 `user` 消息传入，LLM 输出通过 Zod 校验，并且只接受曲库中存在的曲目 ID；无效/超时/网络失败自动回退本地引擎；回复长度受限。
- API Key 不进入前端、日志或错误响应。
- 提示注入的最坏后果是选中曲库内任意歌曲或生成文本，不产生特权操作或代码执行。

### 2.8 部署与容器

- API 与 Web 容器均以非 root 的 `node` 用户运行；数据库仅在 `127.0.0.1:5432` 暴露（供本地开发），不发布到公网。
- 本地 compose 的 PostgreSQL 使用 `trust` 认证，仅限本机绑定与 Docker 内网；这是**演示配置**，生产必须改为密码认证并注入 `DATABASE_URL`（见残留风险 5.1）。
- `.env` 被 `.gitignore` 与 `.dockerignore` 排除；仓库只包含 `.env.example` 占位符。
- 静态服务防止路径穿越：`resolve(PUBLIC_DIR, '.' + pathname)` 后强制 `startsWith(PUBLIC_DIR)`；SPA 回退仅对无扩展名路径生效。
- 安全响应头：`X-Content-Type-Options`、`X-Frame-Options: DENY`、Referrer-Policy、Permissions-Policy、CSP。
- 镜像基于 `node:24-slim` 与 `postgres:16-alpine`；`package-lock.json` 固定依赖树。

### 2.9 测试证据

- 后端 38 项集成测试覆盖：注册/登录/会话失效、密码修改、全设备退出、导出不含哈希、删号确认、管理员越权、歌单所有权、私有歌单、Origin 守卫、隐私模式、订阅切换、助手输入校验。
- 前端 24 项测试覆盖：API 错误映射、播放队列/随机/循环、封面生成、空态与登录门。
- 浏览器实测：Docker 生产构建下登录、播放、歌词、队列、搜索、向导、订阅、管理端增删、私密模式均可用；控制台无未处理错误。

## 3. 审计中发现并已修复的问题

| 编号 | 问题 | 处理 | 级别 |
| --- | --- | --- | --- |
| FIX-01 | API 请求日志默认包含完整 URL，搜索词等用户输入会进入日志 | 增加 Pino `req` 序列化器，只记录路径、方法与 IP，丢弃查询串 | 低（隐私加固） |
| FIX-02 | `/api/history` 会递增公开播放量，任何登录用户可反复调用刷高排行 | 播放历史只写个人记录，不再修改 `tracks.play_count` | 低（数据完整性加固） |

## 4. 攻击面与威胁建模摘要

| 威胁 | 结果 |
| --- | --- |
| SQL 注入 | 不可行：参数化查询 + 固定结构拼接 |
| 存储型/反射型 XSS | 不可行：React 转义 + CSP + 无 HTML 注入点 |
| CSRF | 有效缓解：SameSite=Lax + Origin 白名单 + JSON 解析约束 |
| 越权（水平/垂直） | 已覆盖：会话用户 ID、所有权检查、管理员角色服务端校验 |
| 会话窃取/重放 | 部分缓解：HttpOnly/HTTPS 可配、7 天过期、令牌版本失效；无刷新令牌 |
| 暴力破解 | 速率限制 + bcrypt；无验证码/锁定（原型边界） |
| 路径遍历 | 自定义静态服务已做 resolve + 前缀校验 |
| LLM 提示注入 | 影响限于曲库选曲与文本输出；ID 白名单校验 |
| 依赖/镜像供应链 | lockfile 固定依赖；镜像仅按标签，未按 digest 固定（见 5.4） |
| 数据泄露 | 导出需登录；密码哈希不出 DTO；日志脱敏；DB 本地绑定 |

## 5. 残留风险与生产化要求

> 原型验收不要求修复以下事项，但正式上线前必须处理。

### 5.1 数据库与演示凭据（重要）

- compose 的 PostgreSQL 使用 `trust` 认证且端口绑定 `127.0.0.1`，仅适合本地演示。生产必须使用强密码、TLS、私有网络，并设置 `DATABASE_URL`/`POSTGRES_PASSWORD`。
- 种子账号 `demo@shengyu.app / demo1234` 与 `admin@shengyu.app / admin1234` 是公开演示凭据；生产部署不得保留，需删除或改密，并接入企业身份源或至少强制强密码 + 邮件验证。

### 5.2 会话密钥

- 未设置 `JWT_SECRET` 时 API 生成临时随机密钥并警告，重启会使所有会话失效。生产必须通过环境变量/密钥管理服务注入，并设置 `COOKIE_SECURE=true`、在 TLS 终止层强制 HTTPS。

### 5.3 认证生命周期

- 未实现邮箱验证、找回密码、MFA、登录审计与账号锁定；这些在面向真实用户的部署中应补齐。
- 登录/注册的邮箱存在性提示（注册 409）可用于账号枚举；对外产品可改为统一「已发送」响应。

### 5.4 供应链与镜像

- 依赖使用 caret 范围，依靠 lockfile 锁定；建议在 CI 中执行 `npm audit`/SCA 与 lockfile 校验。
- Docker 镜像使用 `node:24-slim`、`postgres:16-alpine` 标签而非 digest；生产建议固定 digest 并定期重建。
- 本环境 Docker Hub 不可达，故构建使用本机已有镜像验证；在联网机器上可直接拉取同一标签。

### 5.5 限流与多实例

- `@fastify/rate-limit` 使用进程内存；多副本部署时需切换到 Redis 等共享存储，否则限流可被分摊绕过。
- 反向代理之后依赖 `trustProxy` + 代理覆盖的 `X-Forwarded-For`；若直接暴露 API 需重新评估 IP 伪造风险（当前 compose 未发布 API 端口）。

### 5.6 业务边界

- 订阅为模拟：页面明确标注「不扣款」，不接入支付、不存银行卡；生产需单独做支付与订阅合规设计。
- 推荐、播放量、月听众为演示数据；播放历史不改变公开播放量，避免排行操纵。
- LLM 端点属于运维受信配置；如未来允许用户自定义端点，必须增加 SSRF 防护（私网地址黑名单、DNS 固定、出口代理）。

### 5.7 日志与隐私

- API 日志已移除查询串，但仍记录路径、IP 与错误栈；生产需设置保留期、访问控制与合规告知。
- 搜索历史、播放历史可能构成个人数据；已提供导出/删除/隐私模式，但未实现分类保留策略。

## 6. 结论

在原型范围内，认证、授权、输入校验、SQL 参数化、XSS/CSRF 防护、日志脱敏与容器最小权限均达到可接受水平；没有发现高置信度、可直接利用的高危漏洞。两项低风险加固（日志查询串、播放量递增）已在本次评估中修复。上线前应优先完成 5.1（数据库密码与演示账号）、5.2（JWT 密钥与 HTTPS）和 5.3（认证生命周期）三项生产化工作。
